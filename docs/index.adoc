[.lead]
roc-fuzz helps Roc application authors find inputs they did not think to test.
You describe values to try and a rule that must always hold; roc-fuzz explores,
saves any failure, and gives you commands to inspect, reproduce, and minimize it.

.How to use this manual
****
New to fuzzing:: Start with <<why-fuzz-a-roc-application>> to learn what a fuzz
target is, how guided search differs from random input, and when fuzzing fits.
Ready to try it:: Follow <<fuzz-your-first-function>> to test a small Roc module
and work through a saved failure.
Longer campaign:: Continue with <<run-and-maintain-fuzzing-campaigns>> for
bounds, corpora, status output, and failure diagnosis.
Advanced use:: Read <<understand-roc-fuzz-internals-and-advanced-features>> for the
runtime model, allocation assertions, generator dispatch, and raw engine options.
Downstream maintainer:: Read <<add-fuzzing-to-ci>> for a bounded GitHub Actions
pattern and its report contract.
Release verifier:: Read <<release-bundle-provenance>>.
Platform contributor:: Read <<contributing-to-roc-fuzz>> for toolchains,
validation, packaging, and release behavior.
****
