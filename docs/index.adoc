[.lead]
roc-fuzz is a Roc platform for testing pure Roc code past the examples you
write. Fuzz targets check properties over typed inputs with coverage-guided
search; goals, trace rules and allocation measurements check what a passing
campaign exercised; `Model` searches and fuzzes a stateful component described
as a state machine; and `Solve` proves or refutes claims about fixed-width
integer arithmetic. Each target builds into one self-contained executable that
checks declared examples, explores, and keeps findings for inspection, replay,
retention and minimization.

.How to use this manual
****
New to roc-fuzz:: Start with <<why-fuzz-a-roc-application>> to see which
technique answers which question about your code, and where each one stops.
Ready to try it:: Follow <<fuzz-your-first-function>> to fuzz a small Roc
module and work through a saved failure.
Writing targets:: Read <<design-effective-targets>> for generators, examples
and suites, then <<check-what-passing-does-not-show>> to declare goals, trace
rules and allocation checks.
Stateful code:: Read <<model-a-component-and-check-it>> to describe a component
as a state machine, search it under `roc test`, and fuzz the same model.
Integer arithmetic:: Read <<prove-facts-about-integer-arithmetic>> to prove a
claim about fixed-width integers for every value, or find the values that
break it.
Running campaigns:: Continue with <<run-and-maintain-fuzzing-campaigns>> for
bounds, corpora, status output, failure diagnosis and the command reference.
CI maintainer:: Read <<add-fuzzing-to-ci>> for a bounded GitHub Actions
pattern and the report it leaves.
How it works:: Read <<understand-roc-fuzz-internals-and-advanced-features>> for
the runtime model, generator dispatch, the binary input format and raw engine
options.
Release verifier:: Read <<release-bundle-provenance>>.
Platform contributor:: Read <<contributing-to-roc-fuzz>> for toolchains,
validation, packaging, and release behavior.
****
