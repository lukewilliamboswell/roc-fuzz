= Release bundle provenance

roc-fuzz does not store native archives or objects in Git. The independent
`link-inputs.yml` producer builds x64-musl and Apple
Silicon inputs on native GitHub-hosted runners, packages them without
`libhost.a`, and tests the exact archives with fresh hosts and final bundles. It
attests a canonical manifest and each archive but cannot publish. The trusted
default-branch publisher verifies that evidence for the exact same-repository
pull-request ref and SHA before creating an immutable release.

Platform builds restore the reviewed `native-libraries.lock.json` manifest and
archives, verify sizes and SHA-256 digests on downloads and cache hits, validate
their locked release, source and inventory, and build fresh hosts.
The reviewed content hash is the routine trust anchor, so a valid cache hit uses
zero network and does not contact GitHub's attestation service. A corrupt cache
entry is discarded and only the exact locked asset may be downloaded again. The
producer attestations are admission evidence checked once by the trusted
publisher. See xref:development.adoc#generate-platform-inputs[linker-input setup].

After those consumer tests pass, GitHub's attestation service creates
signed SLSA build provenance and an SBOM attestation for the exact
`.tar.zst` bundle. GitHub binds the attestation to the release workflow
and source revision with its OIDC identity, signs it through Sigstore,
and records it in the repository attestations API. No long-lived signing
key is stored in the repository.

Each release also publishes `<bundle>.intoto.jsonl` for offline
attestation verification, and three files beside the bundle that describe
what it holds:

* `<bundle>.spdx.json`, an SPDX 3.0.1 software bill of materials;
* `<bundle>.cdx.json`, the same graph as CycloneDX 1.7;
* `<bundle>.sbom-manifest.json`, the evidence manifest that names the bundle
  and each SBOM by size and SHA-256.

roc-blueprint's SBOM tool writes them through roc-automation's
`actions/sbom-sidecars`, from the reviewed `sbom/composition.json`. The tool
checks that file against `Blueprint.roc` and `Blueprint.lock`: every input of
the environment is either a component or excluded with a reason. It lists
every member of the archive by digest and binds the documents to the bundle's
final bytes. The components are the platform itself and the libFuzzer, Zig
runtime, musl and LLVM runtime code in the native inputs; Zig is a build
dependency. What the documents do not establish is stated as incomplete
coverage, not left out.

The build pins Zig 0.16.0 and the SHA-256 of the `libfuzzer-sys` 0.4.5
source archive. Both targets are compiled against the headers Zig bundles; the
build reads no installed Apple SDK. The libraries are byte-reproducible, so
anyone with that Zig release can rebuild them from the recorded source revision
and compare digests. Native-library archives and the
final platform bundle are separate published and attested subjects, with
independent versions.

== Verify a release

Download a bundle from the GitHub release, then run:

[source,console]
----
gh attestation verify roc-fuzz-<version>.tar.zst \
  --repo lukewilliamboswell/roc-fuzz
----

Verification checks the bundle digest, Sigstore signature, certificate
and repository identity, and transparency information. This project does
not claim a particular SLSA level; the attestation establishes the
workflow and revision that produced the released bundle.

For offline or archived verification, download the matching
`<bundle>.intoto.jsonl` asset and pass it to GitHub CLI:

[source,console]
----
gh attestation verify roc-fuzz-<version>.tar.zst \
  --bundle roc-fuzz-<version>.tar.zst.intoto.jsonl \
  --repo lukewilliamboswell/roc-fuzz
----

The SBOM documents are attested with the bundle. Each names the bundle's
SHA-256, which must equal the SHA-256 of the downloaded file.
