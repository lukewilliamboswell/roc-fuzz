= Understand roc-fuzz internals and advanced features

This chapter explains the runtime model, reusable generator dispatch,
allocation assertions, and the low-level libFuzzer escape hatch. Application
authors do not need this material for the normal target workflow.

== Understand the in-process model

The embedded libFuzzer calls a target thousands of times in the same
process. It does not start a clean executable for every generated input.
This is what makes it fast. Roc's purity means target calls cannot leak
application state or background work into later calls, and determinism
makes saved inputs reliable with the same target and generator.

A reliable target still needs all of the following properties:

* Invalid or unusual inputs return ordinary values such as `Err`, rather
than triggering an intentional assertion or process exit.
* One input normally finishes in less than 10 milliseconds.
* Inputs and allocations have sensible upper bounds.
* Every input terminates.

The runner is a poor fit when one test takes a significant fraction of a
second, can grow without a practical memory bound, or is expected to
terminate the process for invalid input. If a crash, timeout, or memory
blow-up would be a bug, it remains a useful fuzzing failure.

A saved entropy input produces the same typed value and result when the
target and generator are unchanged. Encoded examples use the binary parser and
the same property instead. Keep the executable alongside
important failure artifacts when exact historical reproduction matters.

== Understand generator dispatch

`generator_for` uses Roc's ordinary static dispatch. It is a method
associated with the target's input type, not a runtime interface,
registry, or callback table. Package APIs can require their own methods
with `where` clauses, so the method does not need to be a
compiler-defined name.

The pattern deliberately mirrors `Json.parser_for`:

* `Json.parse` requires its result type to have a compatible
`parser_for` method and asks that type for a JSON parser.
* `Fuzz.target` requires its input type to have a compatible
`generator_for` method and asks that type for a fuzz generator.
* The checker resolves both to a specific method implementation at
compile time. The compiled call has no dynamic-dispatch overhead.

Conceptually, `Fuzz.target` has this requirement:

[source,roc]
----
target : { name : Str, examples : List(Example(a)), test : a -> Outcome, show : a -> Str } -> Target
    where [a.generator_for : FuzzEncoding -> Generator(a)]
----

`FuzzEncoding` currently contains the `Default` policy. Passing a policy
value follows the same shape as `JsonEncoding` and leaves room for
additional generation policies without changing the method pattern.

Use `Fuzz.target` when generation is part of a reusable named input
type. Use `Fuzz.target_with` with an explicit `Generator(a)` for a local
structural input or when choosing between generators for the same type
in different targets.

== Measure allocations and validate traces

Every property callback has an automatic `$property` region. Decoding and
entropy generation finish before that region starts. Named regions use one
native engine:

[source,roc]
----
Fuzz.measure! : Str, (() => a) => { value : a, stats : Fuzz.Stats }
Fuzz.start_measure! : Str => Fuzz.Measurement
Fuzz.Measurement.finish! : Fuzz.Measurement => Fuzz.Stats

measured = Fuzz.measure!("decode", || decode(input))
check_result(measured.value)
if measured.stats.reallocs != 0 { crash "decode unexpectedly reallocated" }

window = Fuzz.start_measure!("manual")
value = build(input)
stats = window.finish!()
use(value, stats)
----

Finish manual windows exactly once, in nesting order. Invalid handles, abandoned
windows, instrumentation limits and arithmetic overflow fail explicitly. The
returned value is still alive at the measurement boundary. Nested windows are
inclusive: a parent contains its children's allocator operations.

[[separate-counts]]
=== Understand the statistics

`allocs`, `reallocs`, `deallocs`:: Separate Roc allocator hook counts. A realloc
counts once as a realloc; its internal allocation and release are not counted
again. `allocs + reallocs` gives the number of allocation requests.
`requested_bytes`:: Sum of each allocation's requested length and each realloc's
full new length. This includes Roc's own allocation headers and excludes the
host's bookkeeping header. It measures traffic, rather than RSS or copied bytes.
`entry_live_allocs`, `entry_live_bytes`:: Roc allocations already live at entry,
including input storage. Allocations made before a window contribute its entry
and peak memory, rather than its allocation count.
`exit_live_allocs`, `exit_live_bytes`:: Memory alive when the window finishes.
This can include a returned value and is not itself a leak.
`peak_live_bytes`:: Actual maximum live requested bytes during the window,
including entry-live memory and simultaneous old/new blocks during realloc.

The broader invocation leak check runs after the complete target adapter returns.
It includes input preparation and teardown, which the property region excludes.
`--no-detect-leaks` disables that check. Metrics remain separate from trace rules
and from diagnostic capture completeness.

Ordinary Roc assertions can inspect any statistic. The allocation assertion
helpers `expect_allocs_at_most!` and `expect_allocs_at_least!` take zero-argument
callbacks (`|| operation(input)`) and count allocations plus reallocations.
Low-level process counters remain available for tightly focused assertions;
assert on differences, never their absolute process-wide totals.

=== Declare logical trace rules

[source,roc]
----
Fuzz.trace_rules!([
    Before("decode", "checked"),
    Count("checked", 1),
    Forbidden("fallback"),
])
measured = Fuzz.measure!("decode", || decode(input))
check_result(measured.value)
Fuzz.mark!("checked")
----

Register rules before the region's first event. Events are direct marks and
completed immediate-child regions. `Before(a, b)` requires both events and every
`a` before every `b`; `Count(event, n)` requires exactly `n`; `Forbidden(event)`
requires none. A grandchild completion is an event of its immediate parent.

Rules are evaluated online even after diagnostic capture fills. Detailed replay
exports ordered events, explicit gaps and unfinished regions. Parent identifiers
and occurrence numbers distinguish repeated names. Neither traces nor assertions
contain timestamps. Capture truncation does not turn an invalid trace into a
passing one and does not invalidate completed allocation statistics.

[[allocation-ratchets]]
=== Accept an exact allocation baseline

Declare examples with names, revisions and `make: || value`, alongside saved
artifacts. `TARGET check` runs each once in a fresh process. `TARGET accept` runs
the same complete inventory once and atomically accepts valid observations.
No warm-up or statistical repetition is needed for these deterministic metrics.

The default file is `<declared-target-name>_baseline.json` in the working
directory: a target named `my_target` uses `my_target_baseline.json`. Override it
with `--baseline=PATH`. Entries are separate by host target and `--profile=NAME`.
An absent entry reports `unbaselined` and permits normal execution.

Every example name, revision, exact input SHA-256, region inventory, metric
version and statistic must match. Reductions and increases both need explicit
acceptance. Failed or rejected examples, incomplete observations and failed
baseline writes preserve the existing accepted file. Check and acceptance never
repeat examples to produce a more convenient result.

=== Binary inputs and witness identity

Structural values use the platform-owned binary format through Roc's existing
`encoder_for` and `parser_for` derivation. Nominal inputs opt in with both methods.
`Fuzz.encode(value)` creates a versioned encoded-value input; `Fuzz.entropy(bytes)`
frames generator entropy. Source examples are encoded into actual mutable seeds.
Host preparation copies bytes and releases temporary Roc values before running
an input. Encoding does not invert arbitrary `Fuzz.map` functions.

The frame is `RFZ`, version byte `1`, form byte (`0` entropy, `1` value), then
payload. Bare historical bytes without the reserved `RFZ` prefix remain entropy.
Artifacts whose interpretation changes across platform versions need their
original executable; cross-version corpus migration is outside this API.
Unsupported versions, malformed
values and exceeded decoding budgets reject. The parser allows at most 1 MiB,
4096 value nodes and 128 total containers, validating counts before allocation.

Generation chooses bias. Preconditions or validated types define validity for
both forms; a range enforced only by a generator cannot protect encoded values.
Logical encoding is not a storage snapshot. Preserve original entropy when
aliasing, capacity or slices are part of a witness. `retain` copies original
bytes, then prints a saved declaration and a decoded representative.

Float encoding follows Roc's floating-point value semantics. Do not rely on
NaN payloads surviving compiler operations; use integer bit inputs for
payload-sensitive properties. With the October 27 compiler, dictionary keys
that are structural records or tuples can crash compiler specialization during
codec derivation. `--specialize=no` avoids that compiler limitation; ordinary
scalar and tag keys work with the default backend.

== Use the libFuzzer interface

`TARGET raw [LIBFUZZER_ARG...]` passes arguments directly to the
embedded libFuzzer CLI. Run this for its complete option list:

[source,sh]
----
TARGET raw -help=1
----

Prefer `run`, `show`, `replay`, `minimize`, and `reduce-corpus` for the
normal workflow. Low-level flags such as `-max_total_time` and
`-max_len` belong behind `raw`; `run` accepts the stable friendly
options listed above. `raw` is an escape hatch for libFuzzer features
the friendly command layer does not yet expose directly.
