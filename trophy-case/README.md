 - `Dict.insert` reallocated the entry list on every overwrite of an existing key, even when the dictionary was uniquely owned and pre-sized. The absent-key path was free; only the `Found` branch copied. Found by allocation assertions, not by any content property -- a copying insert still returns the right answer. Fixed for primitive keys and values by roc `046b7daa26` ("Preserve Dict uniqueness across projected field takes"); `trophy-case/repros/dictInsertOverwrite.roc` now passes.
 - The same overwrite still allocates once per call when the keys and values are refcounted (`Dict(Str, List(U8))` with keys padded past the 24-byte inline threshold), scaling linearly with the number of overwrites. A control loop performing the identical reads of the pre-built keys and values allocates nothing, which attributes the cost to `Dict.insert` itself. Red test: `trophy-case/repros/dictInsertOverwriteRefcounted.roc`
 - `roc check` panics with `postcheck invariant violated: erroneous checked type reached Monotype instantiation` instead of reporting a type error, when a `Try`-returning builtin's result is assigned to a `var` of the unwrapped type (e.g. `$l = List.set($l, 0, 5)`). Reproduces against this platform; not yet minimized -- the same mistake reports a clean type mismatch under a default app module, under the roc repo's alloc-count platform, and under platforms requiring a record-of-function or a nominal type with a hosted effect, so the trigger is still unidentified. Repro: `trophy-case/repros/postcheck_panic_on_type_error.roc`
