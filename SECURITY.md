# Security policy

## Supported versions

Security fixes are made on `trunk` and included in the next release. Only the
latest published release and the current `trunk` branch are supported.

## Report a vulnerability privately

Do not disclose a suspected vulnerability in a public issue, discussion, pull
request, or chat. Use [GitHub private vulnerability reporting](https://github.com/lukewilliamboswell/roc-fuzz/security/advisories/new)
so details remain private while they are investigated.

Include the affected version or commit, supported platform, impact, reproduction
steps or a minimal testcase, and any suggested mitigation. Reports about a Roc
compiler defect should explain how it is exposed through roc-fuzz; the
maintainer will coordinate with the Roc project when appropriate.

The maintainer aims to acknowledge a vulnerability report within 3 business
days and provide an initial status update within 7 days. Confirmed issues will
normally use coordinated disclosure within 90 days, although the reporter and
maintainer may agree to a different timeline based on severity, exploitability,
and release readiness. Credit and disclosure details will be agreed with the
reporter before publication.
